# 0004 — WPM 分母仅计用户实际手动输入的字符，自动跳过字符不计

## 状态

已采纳

## 背景

TypingEngine 提供两个输入辅助：

- **自动缩进**：按 Enter 后自动跳过下一行前置空白字符，用户无需逐个敲空格/Tab
- **智能 Tab**：按 Tab 或空格键跳过当前位置起的一个完整缩进块（4 个空格或一个 `\t`）

这些字符被"跳过"后，光标位置前进，但用户实际按键次数不对应这些字符。如果将跳过字符计入 WPM 分母，开启快捷键的用户会获得人为偏高的 WPM，与关闭快捷键的用户不可横向比较。

## 决策

WPM 分母 = 用户实际触发按键次数所对应的字符数。自动缩进和智能 Tab 跳过的字符**不计入分母，也不计入分子**。

实现上，`useWpm.js` 维护独立的 `typedCharCount` 计数器（与光标位置 `cursorIndex` 分离），仅在用户手动按键推进字符时递增。WPM 公式：

```
WPM = (typedCharCount / 5) / (elapsedSeconds / 60)
```

同一题目、相同代码长度下，关闭快捷键的用户 WPM 会更低——这是**预期行为**，不视为 bug（见需求文档 F03.3）。

## 代价

**优点**
- WPM 真实反映打字速度，不受快捷键策略影响
- 计算口径明确，`useWpm.js` 单元测试可直接验证预期数值

**缺点**
- 不同快捷键配置下同一题目的 WPM 不可直接横向比较；排行榜已通过 `variant_id` 字段记录变体信息，差异来源可追溯
- 需要额外维护 `typedCharCount` 状态，实现稍增复杂度

## 后续

若未来排行榜需要按「是否开启快捷键」分榜，可在 `results` 表增加 `shortcuts_enabled` 字段，当前口径无需变更。
